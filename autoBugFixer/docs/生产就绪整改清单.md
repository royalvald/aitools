## 一、评级总览

| 维度 | 评级 | 说明 |
|---|---|---|
| 管线主流程 | 较完整，有高危并发缺陷 | 状态机 16 状态 + 非法转移防护、FAILED 断点恢复、锁租约回收均为实实现 |
| 安全 | 不达标 | 存在 RCE 面、API 零认证、兜底密钥硬编码 |
| 外部集成 | 半成品 | Jira/禅道/codex 接近可用；deepseek 通道有安全阻断点；全部未与真实系统联调 |
| 测试 | 单测扎实，缺发布安全网 | 249 用例全离线 Mock；无 CI、无真实冒烟、验证断言强度虚高 |
| 持久化/运维 | 单节点可用 | SQLite + 无迁移框架 + 无 HA，多实例直接失效 |

## 二、阻断项（上生产前必须修复）

### P0-1 修复通道 RCE 面：提示注入可转化为宿主机命令执行

- deepseek 通道 `run_command` 以 `shell=True` 直接执行 LLM 生成的命令，**无白名单无沙箱**（`src/autobugfixer/features/fixing/deepseek.py:235-241`）；prompt 中注入的是外部不可控 bug 文本。
- claude 通道默认 `allowedTools` 含 `Bash` 且 `permission_mode=acceptEdits` 免确认（`src/autobugfixer/features/fixing/claude.py:81`、`src/autobugfixer/common/core/config.py:111-112`）。
- codex 通道有 workspace-write 沙箱、argv 不经 shell，是三条通道中唯一可接受的。

整改要求：
- [x] deepseek `run_command` 接入 `CommandWhitelist`（`_run_command` 白名单校验 + argv 形式执行不经 shell；未配置白名单时 fail-closed 拒绝一切命令）
- [x] claude 通道默认移除 `Bash`（`claude_allowed_tools` 默认 `Read,Edit,Write,Glob,Grep`；生产模式预检强制拒绝含 Bash 配置）
- [x] 生产默认 `fix_driver` 仅开放沙箱化通道（`production_mode=True` 时：codex 禁 `danger-full-access`、claude 禁 Bash、deepseek 已内建白名单门禁）

### P0-2 API 零认证 + webhook 无签名校验

- 整个 FastAPI 无认证/授权（`src/autobugfixer/api/routes.py`、`src/autobugfixer/api/app.py`），仅靠默认绑 127.0.0.1 兜底。
- `POST /api/webhooks/{platform}` 无签名/无 token/无平台枚举白名单，任何人可注入伪造工单驱动整条修复流水线；且每次 POST **同步触发预处理烧 LLM**，是现成的 DoS/成本攻击面（`src/autobugfixer/api/routes.py:222-246`）。
- `POST /api/interventions/{id}/resolve` 无鉴权，人工审批关卡形同虚设（`src/autobugfixer/api/routes.py:200-217`）。
- `POST /api/tasks/{id}/retry`、`POST /api/repos` 等危险操作同样无保护。

整改要求：
- [x] 增加认证中间件（`api/auth.py` `TokenAuthMiddleware`：配置 `api_auth_token` 即全接口强制 Bearer/X-API-Token，/api/health 豁免；生产模式未配 token 拒绝启动）
- [x] webhook 增加平台签名校验 + platform 枚举白名单（`WebhookGuard`：HMAC-SHA256 hex / token 恒时比较；白名单外平台 403，生产禁 mock）
- [x] webhook 加限流（每平台固定窗口 `webhook_rate_limit_per_minute`，默认 30/分钟，超限 429）+ 请求体上限（`webhook_max_body_bytes`，默认 1MB）
- [x] CSV 上传增加大小上限（`csv_max_bytes` 默认 2MB，`file.read(n+1)` 截断判定，超限 413）

### P0-3 SSH/Docker 部署假回滚

- 仅 LocalExecutor 实现 snapshot/restore；SSH/Docker 下 `_rollback` 为静默 no-op，但审计照写 `deploy_rollback`、DeployRecord 照标 `rolled_back`（`src/autobugfixer/features/deploying/stage.py:142`、`src/autobugfixer/adapters/env/__init__.py:207-220`）——环境实际未回滚，留痕却说已回滚。Spec 06 §10 已明示此限制。

整改要求：
- [x] SSH/Docker 执行器实现远程快照/恢复（SSH：`cp -a` 全量拷贝至 `<workdir>.snapshots/<tag>` 版本化目录；Docker：容器内 `tar -cf/xf` 归档；均拒绝 workdir=/ 防误删根）
- [x] 回滚能力缺失时显式失败并告警（无 restore 能力或恢复失败 -> `deploy.status=rollback_failed` + `deploy_rollback_failed` 审计 + ops 告警「环境中间态需人工处理」，不再静默标 `rolled_back`）
- [x] Docker exec 超时真正终止容器内进程（命令包 `timeout -k 5 N` 前缀，SIGTERM 后 SIGKILL；容器缺 coreutils 自动降级直跑；外层线程等待兜底返回 124）

### P0-4 并发正确性缺陷（任务卡死 / 双驱）

- **任务永久卡死 WAIT_ENV**：锁冲突时 `session.rollback()` 把同事务刚设置的 `task.environment_id` 一并撤销，而 `wake_wait_env` 跳过该字段为空的任务，无任何机制唤醒（`src/autobugfixer/adapters/env/lock.py:54-56`、`src/autobugfixer/runtime/scheduler.py:137`）。
- **长任务双驱**：任务认领租约只在单个 Stage 步骤内持有、无续期；codex 修复易超过 15 分钟租约（`task_claim_lease_seconds`），之后另一执行者可认领同一任务并行写同一工作区（`src/autobugfixer/runtime/orchestrator.py:195-198`）。
- 调度器无多实例防护（无 leader election）；SQLite 行锁多节点失效。

整改要求：
- [x] 锁冲突回滚改为仅释放锁行（`EnvLockService.acquire` 冲突走 `begin_nested()` SAVEPOINT，`task.environment_id` 等同事务字段不再被整事务回滚撤销——WAIT_ENV 永久卡死根因修复）
- [x] 认领租约增加续期机制（`_ClaimHeartbeat` 后台线程：Stage 执行期间按租约 1/3 周期续约，条件更新 `claimed_until == 本执行者写入值`，被抢注即停）
- [x] 调度器补 leader 锁（`LeaderLock` 单行租约表 + `_LeaderElection`：多实例同轮只放行一个调度者，`scheduler_leader_election` 可关）
- [x] ingest 建任务改走 `transition_task`（DISCOVERED -> ANALYZING 统一入口：校验 + 历史 + `state_transition` 审计）

### P0-5 凭证安全

- 未配置 `AUTOBUGFIXER_FERNET_KEY` 时静默回落硬编码派生密钥 `sha256(b"autobugfixer-dev-key")`，无启动告警（`src/autobugfixer/common/security/credentials.py:22-23`）。
- SSH 使用 `AutoAddPolicy` 自动信任主机密钥，部署通道可 MITM（`src/autobugfixer/adapters/env/ssh.py:173`）。
- 平台凭证走 `bug_platform_config` dict 明文，不经 Fernet。
- environment 表（含 `cmd_whitelist`、`credential_ref`、`deploy_script`）是白名单信任根，但写入途径无鉴权与变更审计。

整改要求：
- [x] 生产模式（非 fake/mock）下未设 `FERNET_KEY` 拒绝启动（`credential_preflight` 复用启动预检机制：API 与调度器 CLI 同口径；开发兜底回落改为显式 WARNING 告警）
- [x] SSH 改 known_hosts 校验（默认 `load_system_host_keys` + 用户 known_hosts + `RejectPolicy`；仅 `strict_host_key=False` 显式回落 AutoAddPolicy 并告警）；增加断线重连（transport 失活自动重建）；SFTP 加超时（channel `settimeout`）
- [x] 平台凭证纳入 Fernet 加密存储（`bug_platform_config` 支持 `credential_ref` 密文键：解密后 JSON 合并注入适配器，明文不再进配置）
- [x] environment 表写入走带鉴权的 API 并记录变更审计（`POST /api/environments`：upsert by name + 预检必败项 + Fernet 加密凭据 + `environment_upsert` 变更审计；凭据密文不回显）

### P0-6 脱敏未接入落库路径

- `redact_sensitive` 仅知识库导出一个调用点（`src/autobugfixer/features/knowledge/export.py:40`）。
- 审计 detail、`FixRecord.prompt_snapshot`/`raw_log`（完整修复 prompt + agent 原始日志，agent 读过 `.env` 类文件即原样落库）、cmd_exec 日志全部不脱敏（`src/autobugfixer/common/core/models.py:166,171`、`src/autobugfixer/features/deploying/stage.py:77-79`）。
- 凭证解密动作（`CredentialVault.decrypt`）无审计记录。

整改要求：
- [x] audit detail、FixRecord prompt_snapshot/raw_log、cmd_exec 日志写入前统一过 `redact_sensitive`（`AuditService.log` 中心化递归脱敏覆盖全部审计；FixRecord/部署 steps_log 落库前脱敏；正则已覆盖 `DB_PASSWORD=x` 前缀形式与 JSON 引号键值形式）
- [x] 凭证解密动作写审计（`CredentialVault.decrypt(on_decrypt=)` 回调：部署期 resolve_executor / 预检 validate_environment / 平台注册表均落 `credential_decrypt` 审计 + 应用日志）
- [x] local 模式默认白名单收窄（默认仅 `echo {text}` / `tail -n {n} {log}`；systemctl 等宿主机服务管理命令须显式配置）
