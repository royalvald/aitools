# 阶段测试用例设计（供 Review 评估开发进度）

> 目的：按流水线阶段给出**可判定的测试用例**，每条标注当前实现状态，Reviewer 通过状态分布即可评估各阶段开发进度与风险。
>
> 依据：PRD（FR-xx）、整体方案设计（§3/§4/§11）、docs/specs/01~08。用例与现有 247 条自动化测试（`tests/`，全绿）对照标注。

## 状态标记规则（Review 口径）

| 标记 | 含义 | 评估结论 |
|---|---|---|
| ✅ 已覆盖 | 已有自动化测试且通过（附测试名） | 该能力**完成且有回归防护** |
| 🟡 缺测试 | 代码已实现，但无用例守护 | 功能算完成，**改动无保护**，补测试即可 |
| 🔴 缺口用例 | 按需求写出的用例，当前实现跑必失败 | **功能缺口**，待开发 |
| ⚠️ 绿灯失真 | 测试存在且绿，但用例手工构造了生产链路不会出现的前置条件 | **测试掩盖缺陷**，需修实现或改测试 |

优先级：P0 = 主流程正确性/生产必须；P1 = 需求点名但可短期绕过；P2 = 演进项。

## 00 状态机与编排（横切基础）

**TC-SM-01 合法迁移表全覆盖** ✅ `test_legal_transitions`

- 说明：验证"任一环节失败可恢复"（NFR-可靠性）。

**TC-SM-03 预处理准入停在 SCORED** ✅ `test_preprocessing_hold_writes_admission_hold_audit`
- Given：评分达准入线；When：`run_preprocessing`；Then：停在 SCORED 并写 `admission_hold` 审计，不自动进 FIXING
- 说明：调度器与 API 触发的行为边界（spec README）。

**TC-SM-04 run_until_blocked 步数上限** 🟡
- Given：任务因缺陷在两状态间无限往返（构造恶意 Fake LLM）

- Then：达到上限即返回，不无限循环
- 说明：防活锁；实现有 `max_steps` 但无用例守护。

**TC-SM-05 人工 retry 从断点续跑（API）** 🟡

- 说明：`routes.py:92-114` 实现完整，但 **retry 端点无任何测试**（含 WAIT_ENV 唤醒分支）。

**TC-SM-06 并发双触发互斥** 🔴 P0
- Given：同一任务已处于执行中（调度器线程跑 FIXING，codex 600s）

## 16 第三轮收尾（安全疑点验证后定稿）

> 对两个安全疑点做代码级验证：白名单参数注入（**被推翻**，三层防御扎实）与 SQL 只读绕过（**半坐实**，见 TC-SEC-09）。功能用例清单至此收敛。

**TC-SEC-09 只读 SQL 多语句在 DSL 层被拒（纵深防御）** 🟡 P2
- Given：验证方案含 `query_db` 步骤，sql=`SELECT 1; DROP TABLE x`
- When：DSL 执行
- Then：应在 DSL 层（`_check_readonly_sql`）拒绝，而非依赖执行器兜底
- 说明：当前正则仅前缀锚定（dsl.py:93 `^\s*select\b`），多语句**能过 DSL 层**；端到端未出事是因为 local 执行器 `sqlite3.execute()` 恰好拒绝多语句（env_executor.py query_db 用 `conn.execute` 单语句语义）。**这是"侥幸安全"**：未来接真实 DB 执行器（B2 范围）时此口子即开。建议 DSL 层加 `;`/多语句拒绝，把偶然变必然。

**TC-ING-12 Webhook 重复投递幂等** 🟡 P1
- Given：平台 webhook 失败重试，同一 payload 投递两次（updated_at 相同）
- When：两次调用 `POST /webhooks/{platform}`
- Then：不重复建任务（ingest 去重已有）；且第二次不并发驱动运行中任务（与 TC-SM-06 同根，webhook 是最易触发的入口）
- 说明：去重逻辑已被 TC-ING-01（轮询路径）覆盖，但 webhook 入口 + 双驱动的组合无用例。

**TC-CFG-01 配置枚举值启动期校验** 🔴 P2
- Given：`INTERVENTION_ESCALATION=susped`（拼写错误）/ `SCORING_ENGINE=V2`（大小写错）
- When：进程启动加载 Settings
- Then：应立即报错退出，而非静默按默认分支行为降级（escalation 拼错 → 永远走 remind；engine 拼错 → 永远走 v1）
- 说明：`config.py` 相关字段均为裸 `str` 无 Literal 校验；错误配置会以"看似正常"的姿态运行，违背 Spec 02 B0"不带病运行"的原则精神。
