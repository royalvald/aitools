AutoBugFixer 功能架构设计图

依据当前代码实现（src/autobugfixer）绘制 · 状态机驱动的单体流水线 · 默认 SQLite + Fake LLM 全链路可跑

数据流主线：缺陷平台 / CSV / Webhook 接入 → 标准化入库（幂等）→ 预处理（完整性分析 → 验证方案 → 难度评分）→ 调度器按优先级出队 → AI 修复（受控工作区 + 经验复用）→ 部署（环境锁 + 健康检查 + 回滚）→ DSL 验证（证据链 + 重试环）→ 经验沉淀 → 平台状态回写关闭。

任务状态机与主流程（当前实现）

DISCOVERED→ ANALYZING⇄ WAIT_INFO→ PLANNING⇄ WAIT_PLAN→ SCORED⇢ MANUAL
SCORED→ FIXING→ DEPLOYING⇄ WAIT_ENV→ VERIFYING⇄ FIXING（重试环）→ LEARNING→ CLOSED
LEARNING→ WAIT_DISCUSS⇢ MANUAL / CLOSED / FIXING
任意状态 → FAILED⇢ 人工重新触发（断点续跑）/ CANCELLED（终态）
自动流转状态 阻塞态：等待人工/环境（Orchestrator 到点即停） 终态（MANUAL 可人工重新触发） 失败态（可断点续跑）
说明：图中内容对应 src/autobugfixer 当前实现；FAKE LLM 模式无需 API Key 可跑通全链路； 调度器当前为数据库轮询（扩展期可换 Redis/RQ）；人工介入是流水线的“阻塞状态”而非旁路流程。
