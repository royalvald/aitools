## 维度锚点（各维度先对照定区间，再在区间内按细节微调）

**fix_difficulty（解决难度）**
- 0-20：改文案/常量/配置项，一处修改即愈；
- 20-45：单函数内的逻辑/条件/计算错误；
- 45-70：跨函数或跨模块的契约、状态同步、时序问题；
- 70-100：涉及 schema/数据迁移/架构调整，或根因不明需排查。

**verify_difficulty（回归验证难度）**
- 0-20：单一断言即可确认（一个接口/一个 UI 元素）；
- 20-45：需 3-5 步操作链或多类型断言；
- 45-70：需数据库交叉核对或日志核查；
- 70-100：需多环境/多数据集/并发场景验证。

**change_scale（改动项规模）**
- 0-20：单文件少量行；
- 20-50：单文件大幅改动或多文件少量；
- 50-100：多文件成体系改动。

## rationale 要求

按"现象 -> 难度证据 -> 分数"组织，引用 Bug 单与验证方案中的具体事实；
三个维度的分数必须分别能从 rationale 反推出（可校验、可解释）。

输出 JSON：{{"fix_difficulty": 0-100, "verify_difficulty": 0-100, "change_scale": 0-100, "rationale": str}}
